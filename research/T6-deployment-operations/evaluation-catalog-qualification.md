# Evaluation catalog qualification

Issue: [#36](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/36). This companion records structured-intake decisions for the existing [Evaluation decision record](evaluation.md); it does not replace that record or its owner/handoff history.

## Scope and evidence boundary

The inventory is the exact 101 rows in the five product/service, platform, status, software and benchmark comparison tables at Evaluation source blob `11e6e7362adb495dd4f789423704a4ef9f5c7fbb`. The source line numbers below identify that immutable input, not future line positions. Existing rule IDs, severity assignments, evaluation types, gates, hypotheses and consumer decisions are unchanged by this catalog companion.

The qualification was performed on 2026-10-18 against already-declared items and versions. Public documentation, immutable Git source and selected hashed publisher distribution members were read. No package was imported or installed to run an evaluator, no dataset or model was downloaded, and no model, judge, generated code or benchmark was executed. Independent reviewers checked source and artifact correspondence; that review does not turn publisher claims into independently measured evaluation results. Every new catalog provenance entry remains `unverified` under the current research workflow.

The frozen `evaluation_suite` spec requires only a nonempty `metric_names` list and `mode`, in addition to CatalogItem's universal identity, version, status, billing and provenance fields. The proposed metric sets are bounded available capabilities, not exhaustive product inventories. A public versioned benchmark method can qualify without an installed runner or a completed evaluation. A metapackage can support its publisher-described capabilities while explicitly leaving implementation dependencies ranged. Missing operational prices remain `billing_class: unknown`; licensing, data admission, deployment permission, an empirical score, a fixed sample-size rule and a builder-selected threshold are not invented catalog admission prerequisites.

`offline` describes the explicitly scoped finite batch/evaluation workflow and does not imply no network. TruLens `both` follows its documented arriving-trace and batch paths. AILuminate `online` follows the publisher's named Official Online service path; it does not mean continuous production monitoring. The Artificial Analysis performance profile's `online` scope is repeated live-endpoint probing, not an installed monitoring product. No claim is made that these unlike methods or their numeric outputs are interchangeable.

`active` means the cited published item/method is available at source access; it is not a maintenance, compatibility or fitness warranty. Source metadata declaring Alpha, Beta, Pre-Alpha or preview remains `preview`. Current maintenance/default-branch caveats are retained in the relevant profile. Software-license identifiers apply only to the read source; all-in inference/judge/compute/data costs and rights are separate. Promptfoo's only `free` classification is expressly limited to the documented Community software entitlement.

## Required follow-through and unchanged boundaries

Repository schema/intake checks validate JSON shape, references, URL/date syntax and local consistency; they do not certify the publisher claims or reproduce evaluator behavior. The submission's actual validation receipt must name its exact source tree and commands. Newly prepared records remain proposals until reviewed and merged through the ordinary repository process.

For note-only candidates, the next engineering action is to select and source-check the exact item/version and metric/mode scope identified above. That is not a requirement to buy a plan, call a model or invent an undocumented release. Historical comparisons remain useful evidence without being promoted as current recommendations. Later per-build use still needs the existing decision record's workload, data, model, evaluator configuration, billing, reproducibility and gate policies. This intake neither executes those build-specific choices nor changes the literal issue acceptance criteria.
