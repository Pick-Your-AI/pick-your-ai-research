# OpenRouter — desk-research profile

Status: draft for owner review. Operator: OpenRouter. Classification: Partial competitor, Infrastructure provider, Data source (analyst judgement).

## Workflow and competitive overlap
Discovery is coupled to execution, reducing friction between comparing a model and trying a provider. This is a strong model-first and cost-first substitute.

## Technical evidence and limitations
The Models API documents metadata and filtering; provider-routing behavior is a separate concern. Default modality filtering can omit specialized model types, so import scope must be explicit.

## Economics, access and rights
Usage pricing and platform fees require their own source checks. A listed model price is not a complete bill and does not establish rights to repackage the full catalog.

## Strategic implication and next test
Map canonical model identity separately from provider endpoint, region and supported parameters. Test fallback behavior against privacy constraints; preserve #5/#6 ownership and send cost semantics to #39.
