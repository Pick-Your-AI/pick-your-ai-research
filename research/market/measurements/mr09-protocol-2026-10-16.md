D1–D5 are bounded feasible targets, not completed measurements. M/G rows are
explicit unexecuted coverage gaps, not fabricated small models. No random model
or synthetic test fixture may fill them. A larger context boundary (8,192 total)
is deferred to a reserved GPU session rather than deliberately causing device
contention. OOM is recorded if observed, never intentionally induced on this
shared device. FP8, weight quantization, graph pools, paged continuous batching,
prefix sharing, tensor/pipeline parallelism and offload are excluded here.

Optional INT4 backend: install `optimum-quanto==0.2.7 --no-deps` into a task-local
temporary directory, add only that directory to the measurement process path,
and pin its version. An unsupported import/backend is a separate outcome, not
a replacement BF16 run. Download only the pinned model's config/tokenizer and
safetensors into temporary storage outside Git; publish file hashes, not weights.
The model publisher marks Apache-2.0; do not infer rights for other cached models.

## Isolation, phases and counters

Three fresh Python processes per D cell. Set seed 6109, eval/inference mode,
greedy argmax, fixed 32 decode forwards without EOS stopping. Build independent
non-sensitive artificial prompts from repeated public-domain words, tokenize
once and truncate/repeat deterministically to the exact requested token count.
No generated text is retained; only token counts and IDs/checksums needed for
reproduction. Equal-length batch rows are admitted active sequences, with zero
queue. This exercises a real pretrained model with synthetic input, not a
synthetic memory result. It does not assess answer quality.

Preflight requires at least 2 GiB free and sets this process's allocator limit
to at most 2 GiB (or 12.5% of reported device memory, whichever is lower).
Abort rather than evict another workload. Stop after an OOM or unexpected
runtime error and record the phase; do not retry with changed hidden settings.

Capture baseline (after CUDA initialization), loading CPU weights onto GPU,
warm-up (64 prompt tokens plus one cached decode), measured prefill, 32-token
decode, and steady-state live cache. Before each measured phase: synchronize,
reset peak memory statistics; after: synchronize then capture current/peak
allocated and reserved bytes, plus driver free/total bytes. Never empty the
allocator cache inside a measured phase. After warm-up, release only this
process's outputs and use `empty_cache` before measured prefill; this reset is
recorded and preserves loaded weights. Each fresh process releases its own
resources on exit. No graph phase exists for eager execution; record it as
not applicable, not as zero overhead. Runtime phase peaks are measured by
allocator high-water counters, not a polling approximation.

Allocated bytes are live tensor allocations managed by this process's PyTorch
allocator; reserved bytes are the allocator's backing pool, including reusable
blocks. Reserved already contains allocated: do not sum them. CUDA contexts,
libraries and other processes are outside these counters. Driver free/total
and `nvidia-smi` values are supplemental device observations and cannot replace
allocator counters or isolate process footprint under WDDM. Peaks from separate
phases need not occur simultaneously. Capture actual native KV tensor payload
at prefill/steady state separately from allocator reservations. INT4 payload
includes quantization metadata and a BF16 residual; nominal four-bit arithmetic
alone cannot predict it. FP32 computation/workspace may coexist with BF16 weights.

## Estimators, errors and failures

Only compare quantities with matching semantics and tested inputs. Record
estimator revision, exact model/precision/context/cache/concurrency inputs and
raw outputs. PR #75 `t2-dense-kv-memory` 0.2.0 at commit
`9e66622a4b2698a9305274f05da9c15ae5d90b8c` has Qwen2.5-specific pinned
weight/geometry constants and assumed runtime/headroom. Its unmodified outputs
are not comparable to SmolLM2 allocated/reserved peaks. A separate transparent
SmolLM2 weight-plus-KV payload formula can be checked against like tensor payload:
`2 × layers × KV_heads × head_dim × cache_tokens × active_sequences × bytes_per_KV_element`.
Pin geometry from the model config; it is a payload estimate, not total VRAM.
Do not compare a headroom-adjusted device budget with active tensor allocations.

For comparable positive measured quantities, signed error = estimate − measured;
absolute error = abs(signed error); signed relative error (%) =
100 × (estimate − measured) / measured. Zero/negative/missing measurements or
mismatched semantics yield no numerical relative error. Report every repetition,
sample count, min/max/range and median. This small sample's maximum is an
observed extreme, never a guaranteed error bound. No MVP tolerance is approved;
@CompleteDotTech must set a decision threshold before pass/fail judgment.

Outcomes are: success; OOM_loading; OOM_prefill; OOM_decode; runtime_error with
phase; unsupported; estimator_rejection/missing_inputs; or unexecuted with
reason. Preserve failures without invented numerical errors. A failed actual
load following an estimator fit claim is an unsafe prediction only when inputs,
capacity and semantics match; conservative rejection is a different event.

## Pins, evidence and review gates

The script records command/config, UTC timestamps, Python/package/build versions,
GPU name/count/driver, allocator backend, artifact file SHA-256, model revision,
device placement, actual tokens, active sequences, phase counters and failures.
Protocol and script hashes distinguish later edits. Report bytes and explicitly
convert GiB=2^30 bytes, GB=10^9 bytes, MiB=2^20 bytes.

## Pre-execution clarification and concrete MoE pin — 2026-10-16

Before the first GPU run, M1–M4 are pinned to
`allenai/OLMoE-1B-7B-0924-Instruct`, revision
`7f1c97f440f06ce36705e4f2b843edb5925f4498` (main/DPO), Apache-2.0.
The [publisher API](https://huggingface.co/api/models/allenai/OLMoE-1B-7B-0924-Instruct)
and [pinned config](https://huggingface.co/allenai/OLMoE-1B-7B-0924-Instruct/blob/7f1c97f440f06ce36705e4f2b843edb5925f4498/config.json)
report 6,919,161,856 BF16 parameters, 16 layers, 16 attention/KV heads,
hidden size 2,048, 64 experts with 8 selected per token, and 4,096 positions.
The [pinned safetensors index](https://huggingface.co/allenai/OLMoE-1B-7B-0924-Instruct/blob/7f1c97f440f06ce36705e4f2b843edb5925f4498/model.safetensors.index.json)
reports 13,838,323,712 tensor bytes (12.888 GiB), excluding runtime/cache.
All experts' resident weights count despite sparse active routing. Metadata
only was retrieved; no MoE weights were downloaded. This exceeds the 2 GiB
process cap and observed ~4 GiB free. Reclaiming or reserving hardware is an
owner action; total 16 GB by itself does not prove a safe full-resident run.
Transformers 5.0.0 contains the `olmoe` implementation; actual backend/cache
compatibility remains untested. M rows retain prompt256/2048, decode32 forwards,
active1/2 and BF16/optional INT4 exactly as specified above. Pin shard hashes
on the authorized host before eventual execution; no unknown checksum is invented.

Prefill predicts one next token, followed by 32 decode forwards predicting 32
more. Therefore 33 token predictions are produced, only 32 forwarded into the
cache, and the terminal cache contains prompt+32 positions. Record all three
counts. "Steady state" below means the instantaneous post-decode live-cache
snapshot; it does not establish a stable serving regime or throughput SLO.
No latency conclusions are drawn from this shared GPU.
