## Fit is a conditional estimate

The [Local AI planner](https://logarithmicspirals.com/tools/local-ai-vram-calculator-gpu-planner/) describes weights + KV cache + runtime overhead and exposes runtime, quantization, context and multi-GPU inputs. [llmfit](https://github.com/AlexsJones/llmfit) documents hardware-aware estimates and local measurements. [ModelFit](https://modelfit.io/) describes bandwidth-derived speed estimates. These are useful starting points, not mutually validated accuracy guarantees.

For conventional attention, an analytical cache approximation is 2 × layers × KV heads × head dimension × cached tokens × bytes per element × concurrent sequences. Record architecture exceptions, shared prefixes, sliding windows and allocator behavior before using it. Weight quantization and cache quantization are separate parameters. MoE active parameters do not by themselves establish resident weight memory; offloading and runtime behavior must be known.

The [vLLM parallelism guide](https://docs.vllm.ai/en/latest/serving/parallelism_scaling/) distinguishes execution configurations. Summing GPU VRAM and multiplying bandwidth is not a sufficient proof of fit or throughput: per-device shard requirements, interconnect and parallelism strategy need measurement. These are risk hypotheses to test, not new universal compatibility rules.

**Unit caution, bounded to the inspected paths:** llmfit's `estimate_memory_gb_with_kv` computes weight term `params_b × bpp` (decimal-GB magnitude), adds exact KV divided by `2^30` (GiB magnitude), then fixed `0.5`. Hardware RAM/VRAM probes generally divide bytes by `2^30`; its MoE helper also uses `2^30`. The returned mixed-term scalar cannot be converted to bytes by attaching one universal unit. Keep raw values, record the path and reconstruct terms separately before comparison; this is a finding about these pinned functions, not a claim that every output is wrong. ModelFit's CLI probes similarly use binary divisors/rounding while catalog load fields say GB without an inspected byte definition. That prevents assuming exact byte equivalence. Planner's inspected exact KV path uses decimal GB, while manual hardware inputs retain the user's unit interpretation [F02–F05, F08–F09, F12].

**Pool caution:** a runtime may reserve cache independently of demanded KV. vLLM's release-pinned guidance describes preallocated cache, preemption and separate parallelism choices [F13]. Do not compare a weight/KV heuristic directly to total reserved memory, or add demanded KV a second time on top of the pool that already contains it. The pinned, merged PR #75 accounting distinction is reused; no constant overhead is adopted as an approved policy.

  input, ratio: ramBudgetRatio(input.ramGb),

  exactModelMatches: rows.filter(m =>
    m.name === 'HuggingFaceTB/SmolLM2-135M-Instruct' || m.name === 'SmolLM2 135M')
