## Program coordination

Refresh the native hierarchy and active PRs/runs; the 18 epics and 110 work packages in [the epic directory](apple/README.md) are a publication snapshot. `IOS-XX.YY` coordinates are planning identifiers, not issue numbers or T0–T6 tiers. Use each issue's named output and link its acceptance record after the repository decision; no location is assumed while that decision remains unresolved.

Resolve Pick-Your-AI/pick-your-ai-apple#21 scope, Pick-Your-AI/pick-your-ai-apple#22 framework/OS/repository and Pick-Your-AI/pick-your-ai-apple#23 shared-service integration before dependent implementation. SwiftUI or any shared framework is a candidate, not a mandate from this prompt. Existing Swift conformance requirements must be reconciled explicitly if a different approach is accepted, not silently dropped. iPhone and adaptive iPad are the proposed baseline subject to the existing scope decision. Mac, watch, TV, spatial and other platforms require the existing expansion gate, not automatic inclusion.

Consume one canonical website/Android service and data implementation. Apple service-titled work packages deliver Apple requirements, adapters, lifecycle behavior and receiving acceptance. In particular do not build a second catalog publisher, pricing engine, account service or saved-build backend. A prerequisite with Android in its title requires the named shared output, not the Android UI or Play release. Where an unshipped client is represented by a published conformance harness, report actual runtime parity as unverified rather than manufacturing a launch blocker or parity claim.
