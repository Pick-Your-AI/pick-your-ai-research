# Mobile issue and acceptance index

Every covered issue has one applicable execution prompt, [shared rules](SHARED.md) and [launch instructions](README.md). Program and epic prompts coordinate existing native children; this is not a second checkbox tracker. [coverage.json](coverage.json) retains the exact acceptance criteria, implementation steps, validation text, scope, output/review boundary, native prerequisite URLs and information/review references for every row. [Project fields](project-fields.json) retains both independently identified field sets. Refresh live before execution.

Android acceptance paths below are intended paths in `Pick-Your-AI/pickyour.ai`, not claims those files exist. Apple outputs are named by the issues, while their location remains subject to Pick-Your-AI/pickyour.ai#184 and shared integration Pick-Your-AI/pickyour.ai#185; do not invent file locations. Research inputs retain their original research paths. Every record requires criterion results, exact artifact identity, negative/recovery evidence, limitations and receiving review.

Common authority handoffs in SHARED.md apply where relevant in addition to each row’s native output prerequisites and information/review references. These links do not assign duplicate shared implementation. Reviewer roles are requirements, not named ownership.
